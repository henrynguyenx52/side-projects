# SoulX-FlashHead Lite — Local Apple Silicon Implementation Instructions

## Mission
Build and **benchmark first** a photorealistic audio-driven talking-head prototype using **SoulX-FlashHead Lite**, running **entirely locally** on a **Mac mini M4 with 24 GB unified memory**. Input: one realistic JPG/PNG portrait and Vietnamese speech WAV generated by **VietNeuTTS**. Output: a talking-head video with natural mouth movement and subtle head motion. Do not use cloud inference, paid APIs, or NVIDIA/CUDA.

**Critical constraint:** Previous Ditto experiment took **50 seconds of pure inference for 10 seconds of output (RTF = 5)**. The new model must demonstrate **inference RTF < 1** (strictly less than 10 seconds for 10 seconds of audio/video) before any major integration. Aim for at least 10 FPS output; measure first-frame latency separately. There is **no verified evidence** that FlashHead Lite meets this target on a base M4. Do not claim real-time until measured.

## Repositories and evidence
- Official: https://github.com/Soul-AILab/SoulX-FlashHead
- Apple Silicon community fork: https://github.com/manmastersg/soulX-flashHead-local
- Official weights: https://huggingface.co/Soul-AILab/SoulX-FlashHead-1_3B

The official Lite performance claims are for an **RTX 4090**, **not Apple M4**. The community fork advertises MPS support but has minimal community validation. Treat it as experimental, inspect code before running setup scripts, and verify that Lite mode actually uses the Lite checkpoint and LTX VAE. Do not confuse MPS GPU with Apple's Neural Engine: PyTorch MPS uses Metal GPU acceleration, not automatically ANE.

## Phase 0 — Safety, feasibility, environment
1. Confirm `uname -m` is `arm64`, available disk, memory pressure, macOS and Python versions.
2. Clone the community fork into a dedicated workspace; inspect `README.md`, `setup.sh`, `run.sh`, `requirements.txt`, `settings.yaml`, `generate_video.py`, `gradio_app_streaming.py`, and relevant inference code before executing anything.
3. Record exact git commit hashes for both fork and upstream. Compare substantive modifications, license restrictions, and download sources. Do not execute unreviewed shell scripts blindly.
4. Use a Python virtual environment. Avoid global package changes and unnecessary large downloads. Confirm model disk footprint before download.
5. Check PyTorch MPS support:
   ```bash
   python -c 'import torch; print("MPS available:", torch.backends.mps.is_available())'
   ```
6. Do not enable a public Gradio share link. Bind UI/API to `127.0.0.1` only. Keep portrait and audio files local.
7. If Lite inference is unsupported on this fork, document the exact blocker rather than silently switching to Pro, CUDA, CPU-only execution, or a different model.

## Phase 1 — Minimal local proof of concept
1. Install only dependencies required for **Lite + MPS**. Exclude CUDA-only `flash-attn`, `sageattention`, `xformers`, `xfuser` unless explicitly needed by a compatible implementation; do not install CUDA PyTorch wheels.
2. Download the **official** FlashHead weights and `facebook/wav2vec2-base-960h` from their verified sources. Verify expected `Model_Lite` and `VAE_LTX` components exist.
3. Prepare a **single front-facing photorealistic portrait** and a **10-second Vietnamese speech WAV**. Use a consistent test set across runs. Normalize audio to the sample rate expected by the actual implementation (the upstream example uses 16 kHz); do not assume audio format without checking.
4. Run Lite inference through the fork's verified CLI (`generate_video.py`) or local Gradio entry point. Avoid a public share URL.
5. Generate a short 2–3 second smoke test before the full 10-second benchmark. Inspect facial identity, mouth synchronization, head movement, artifacts, and temporal consistency.
6. Do not add VietNeuTTS runtime integration, WebRTC, frontend, or compositing until the benchmark gate passes.

## Phase 2 — Accurate performance benchmark
Measure **pure warmed-up inference** independently from startup, checkpoint loading, downloads, preprocessing, and MP4 encoding. Also measure end-to-end processing separately.

- Warm up at least twice, then run **3 repeat trials** of the same 10-second WAV and portrait; report median and individual measurements.
- Synchronize MPS before and after timed GPU sections with `torch.mps.synchronize()` when supported.
- Report: output frames, actual output FPS, inference seconds, `RTF = inference_seconds / audio_duration_seconds`, effective generated FPS (`frames / inference_seconds`), first-frame latency, peak unified-memory usage/memory pressure, and any CPU fallback.
- Profile at minimum: audio feature extraction (wav2vec2), diffusion/transformer generation, Lite LTX VAE decoding, face crop/compositing, and frame encoding.
- Check frame count and output duration: do not improve RTF by silently truncating audio, dropping required content, or changing the output duration.
- Benchmark at realistic resolution/settings, then repeat with clearly labeled lower-resolution experiments if needed.
- Log hardware/software versions, exact model mode, seed, steps, dtype, resolution, batch/chunk size, audio duration, and git commit.

### Acceptance gate
**PASS** only if: 10 seconds of audio produces approximately 10 seconds of usable talking-head video; pure inference is **<10 seconds** (RTF < 1), output is at least 10 FPS, identity remains photorealistic, Vietnamese lip sync is acceptable, and memory remains stable on the 24 GB Mac.

If the gate fails, report the bottleneck and a realistic improvement estimate. Do **not** represent RTX 4090 benchmarks as Mac results.

## Phase 3 — Targeted optimization (only if profiling justifies it)
In priority order, test one change at a time and keep visual A/B samples:
1. Keep weights resident and reuse portrait conditioning and audio features when valid.
2. Remove unnecessary CPU↔MPS tensor transfers and per-chunk synchronization.
3. Inspect unsupported MPS operations and CPU fallback; document their actual costs.
4. Tune Lite-specific settings: steps, dtype, attention implementation, chunk length, resolution, and decoder strategy **only where supported**.
5. Investigate whether the LTX VAE decoder is the main bottleneck before attempting an invasive port.
6. Consider Core ML/MLX conversion **only for a measured bottleneck** and only after validating operator support and numerical quality. Do not promise a 5× speedup from changing backend.
7. Re-run the same 10-second benchmark after each optimization and retain the best reproducible configuration.

## Phase 4 — Streaming prototype (only after benchmark PASS)
1. Integrate VietNeuTTS as a **local** audio source; initially use pre-generated WAV, then evaluate incremental audio chunks if VietNeuTTS supports them.
2. Maintain timestamped audio/video chunks, continuous face identity, and temporal consistency at chunk boundaries.
3. Expose a localhost-only streaming API; use WebRTC only if it meaningfully improves delivery. No cloud services.
4. Preserve the upper body and shoulders where possible; head movement should be subtle. Forearm gestures are a separate later feature and should not be simulated by distorting the torso.
5. Measure sustained throughput over 3–5 minutes, startup latency, audio/video sync drift, thermal throttling, and memory pressure.
6. Distinguish **RTF < 1** from low interactive latency: both matter for live use.

## Deliverables
- `README.md`: exact Mac installation and run steps, known limitations, and rollback/uninstall steps.
- `benchmark.py` or equivalent reproducible benchmark script with correct MPS synchronization.
- `results/benchmark.json` and concise `results/report.md` with all timing breakdowns and machine details.
- One short local test output (not committed if it contains a real person's image or voice).
- A clear **GO / NO-GO** decision against the acceptance gate, including next actions if not feasible.

## Non-negotiable rules for the coding agent
- Use **Lite**, not Pro, unless explicitly requested.
- **Mac M4 / 24 GB / local only**; no CUDA, rented GPU, or remote inference.
- Do not invent benchmark numbers or claim MPS support means real-time.
- Do not download or install multi-GB alternatives without asking first.
- Preserve the source portrait's identity; do not substitute a stylized 3D avatar or lip-sync-only model.
- Keep implementation simple, readable, and reproducible; prioritize benchmarking before architecture work.
